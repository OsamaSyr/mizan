# The real-world corpus

> Measuring MIZAN against prose nobody on this project wrote.
> Collected 2026-10-02. Numbers regenerated by `tests/real_corpus.py`.

## Summary

473 quotations and 560 no-quotation paragraphs, gathered from two publishers
in five languages, with `robots.txt` obeyed on every request.

The corpus found three things the self-referential suites could not:

1. **The printed-reference tier is being thrown away.** It identified the
   publisher's cited verse 262/262 times (100%) and 194 of those correct
   answers were discarded by a similarity threshold before reaching the
   report. Partial quotation — the norm in real writing, absent from
   index-derived tests — is the trigger. §3.
2. **On no-quotation prose MIZAN is noisy but honest.** 38.3% of paragraphs
   produced some finding, which is bad; but only 2 of 64 findings were false
   *attributions* to a named translation. It refers too much; it does not
   claim authorship falsely. §3.
3. **The noise has a measured cause**, not a mysterious one: spurious spans
   cluster at the `MIN_SPAN_WORDS = 6` floor, median width 7 words.

Detection on real text (33.8%) is far below the index-derived figures, and
§4 is explicit about what that does and does not mean.

**Nothing here measures how often publishers misquote.** That was not
measured, cannot be measured from this corpus, and is not claimed.

## Why this exists

Every measurement in this repository up to now has fed the index's own text
back to itself. That is the right way to prove the comparison mechanism and to
calibrate the thresholds, and it is where the 0.008% false-alarm figure on
12,118 approved texts comes from. It is a real result and it stands.

What it cannot tell you is whether the system survives contact with published
writing. Real da'wah prose has curly quotes, ellipses dropped into the middle
of a verse, footnote markers glued to the last word, "God" where the index
says "Allah", square-bracketed clarifications inserted by the translator, and
a citation convention that changes with every publisher. A test built from the
index will never contain any of that, because the index does not.

So we went and got some.

## 1. Sources, and the permission under which we used them

Every host's `/robots.txt` was fetched and parsed **before any other request**,
re-checked on every run (including runs served entirely from cache), and the
result recorded in `data/real/manifest.json` under `robots`. The crawler is
single-threaded per host by construction; there is no parallel path.

| Setting | Value |
|---|---|
| User-Agent | `Mizan-Research/0.1 (Islamic AI Challenge 2026; contact osamaabdullh2002@gmail.com)` |
| Delay between requests to one host | 2.5 s minimum, or the stated `Crawl-delay` if longer |
| Concurrency against one host | 1 (no threads anywhere in the collector) |
| Raw HTML cached | `data/real/raw/<host>/` — reruns are fully offline |

### Used

| Host | robots.txt | Crawl-delay | What we took |
|---|---|---|---|
| `www.islamreligion.com` | `User-agent: * / Disallow:` — nothing disallowed | none stated → 2.5 s | Da'wah articles, English / Hindi / Tagalog |
| `islamqa.info` | `Disallow: /_next/` only; article paths permitted | none stated → 2.5 s | Q&A answers, Urdu / Bengali / Hindi |

`islamreligion.com` numbers its articles in **one id space shared across all
fifteen language editions** — `/articles/1190/` and `/hi/articles/1190/` are
the same piece of writing. That is unusually good for this purpose: a
per-language score compares the same house style and the same citation
convention across languages, instead of confounding "this language is harder"
with "this publisher is different".

`islamqa.info` is the only verified source of Urdu and Bengali prose served as
readable HTML. Its citation style is also harder, which is a feature: it
prints a surah **name** rather than a number, and in Bengali the verse number
is in Bengali digits — `(সূরা নিসা: ১১৬)`, not `(4:116)`. A corpus drawn only
from publishers who print `2:255` would flatter the system.

### Checked and not used

| Host | Why not |
|---|---|
| `aboutislam.net` | robots.txt permits crawling, but the site has no Urdu, Bengali or Hindi content — the sitemap contains zero characters in those scripts. English-only, and we already had English. |
| `hadithbd.com` | robots.txt explicitly names and bans `ClaudeBot`, `GPTBot` and `CCBot`. The server also returns HTTP 403 behind Cloudflare. Clear operator intent; **skipped, not worked around.** |
| `islamhouse.com` | robots.txt permits it, but article pages are download stubs — 85 KB of navigation chrome wrapped around links to PDFs. The PDFs use custom font encodings that extract as garbage. Confirmed previously and again here. |
| `ur.wikipedia.org`, `hi.wikipedia.org` | Permitted (`Crawl-delay: 5`), but verses sit in bare `<p>` delimited only by `{ }` braces, with no semantic markup. Brittle extraction for little gain once islamqa was working. |
| `bn.wikipedia.org` | Permitted, and genuinely well marked up (`blockquote.quotebox-quote` plus the U+06DD ayah marker). Not used only because we ran out of collection budget; if Bengali coverage needs strengthening this is the first place to go, **via the Wikimedia dumps rather than crawling.** |

## 2. What was collected

Run `python3 scripts/collect_corpus.py` to reproduce (or `--offline` to rebuild
from the cached HTML without touching the network).

**570 pages fetched → 473 quotations + 560 no-quotation paragraphs**, across
five languages — all five that the index covers.

| Language | Quotations | With a printed citation | Source |
|---|---:|---:|---|
| English | 130 | 94 | islamreligion.com |
| Urdu | 126 | **0** | islamqa.info |
| Hindi | 94 | 70 | islamreligion.com (85), islamqa.info (9) |
| Tagalog | 85 | 63 | islamreligion.com |
| Bengali | 38 | 35 | islamqa.info |
| **Total** | **473** | **262** | 2 hosts |

**Urdu contributes no ground truth, and that is worth being explicit about.**
On the Urdu edition of islamqa the verse rendering sits in a `class="aaya"`
span while the citation, when present at all, appears in a *different*
paragraph or only beside the Arabic original. Our collector will not guess
across that gap. So Urdu's 126 items count toward detection and the state
distribution, but Urdu is absent from every reference-accuracy figure. A
reference-accuracy number for Urdu would have to be fabricated, so there
isn't one.

(Incidentally, the Urdu edition puts the **Urdu rendering** inside `aaya`,
whereas the Hindi edition puts the **Arabic** there. Same class, different
contents, same publisher. The collector distinguishes them by script.)

Counts are written to `data/real/manifest.json` and restated in
`tests/results_real.json`; treat those files as authoritative over any number
typed into prose here.

**Two files:**

- `data/real/corpus.jsonl` — one record per quotation found. Fields: `id`,
  `source_url`, `source_host`, `lang`, `published_text` (the quoted span as
  published), `printed_ref` (the publisher's own citation, or `null`),
  `context_before`, `context_after`, `retrieved_at`, `license_note`.
- `data/real/negatives.jsonl` — paragraphs of the same authors' prose that
  contain **no** quotation, for the false-positive probe.

The negative set is filtered hard. A paragraph is excluded if it contains any
quote glyph, any verse reference, or any bare `n:m` pair. A false-positive
probe run against a dirty probe set measures nothing.

### Ground truth

**The publisher's own printed citation.** When a page prints "(Quran 2:255)"
beside a quotation, the publisher is asserting which verse that is, and we
take the assertion at face value.

This is a real limitation and worth stating plainly: it is the publisher's
claim, not an independent adjudication. It is, however, the only ground truth
available at this scale that does not involve us deciding what a verse says —
which is exactly the authority MIZAN is designed never to take.

Surah-name parsing is strictly table-driven (`SURAH_NAMES` in the collector).
An unrecognised name yields `printed_ref: null` and the item drops out of the
accuracy denominator rather than entering it with a guess. An earlier, looser
version read the Urdu phrase `[یعنی :محسود]` ("[that is: the envied one]") as
surah 113 purely because a bracketed phrase preceded a colon and a number. One
bad ground-truth entry silently corrupts the figure it feeds.

## 3. What was measured

`python3 tests/real_corpus.py` — results in `tests/results_real.json`.

### Two conditions, because the difference is itself the finding

MIZAN's detector has three tiers, and the cheapest — tier (a) — is simply
reading a printed `(Quran 2:255)`.

- **(a) citation stripped.** Only the quoted span is fed in. Harder than
  reality, and measures the lexical tier alone: the part that has to work when
  an author quotes without citing.
- **(b) citation in place.** The text as it actually appears on the page. A
  publisher running MIZAN pastes the paragraph as published; they do not
  delete their own footnotes first.

Reporting only (a) understates the product. Reporting only (b) hides the hard
part. So both are reported.

### Detection — did MIZAN locate a quotation at all

| Language | n | (a) citation stripped | (b) citation in place |
|---|---:|---:|---:|
| English | 130 | 50.8% | 53.8% |
| Bengali | 38 | 28.9% | 39.5% |
| Urdu | 126 | 27.0% | 27.0% |
| Hindi | 94 | 24.5% | 26.6% |
| Tagalog | 85 | 18.8% | 18.8% |
| **All** | **473** | **31.7%** | **33.8%** |

This is much lower than the self-referential suites, and the reasons are
specific rather than mysterious — see the headline finding immediately below,
which accounts for most of the gap. Note also that extraction is heuristic:
some captured spans are hadith or scholarly quotations rather than Quranic
ones, and those can never be detected because there is no approved Quran
translation for them to match. That depresses the denominator in a way we
have not fully separated out.

### Reference accuracy — did it resolve the verse the publisher cited

Of the items MIZAN located **and** the publisher had cited:

| Language | (a) stripped | (b) in place |
|---|---:|---:|
| English | 38/60 · 63.3% | 40/64 · 62.5% |
| Bengali | 5/11 · 45.5% | 7/15 · 46.7% |
| Hindi | 8/20 · 40.0% | 10/22 · 45.5% |
| Tagalog | 4/12 · 33.3% | 4/12 · 33.3% |
| **All** | **55/103 · 53.4%** | **61/113 · 54.0%** |

Urdu is absent here for the reason given in §2.

### State distribution (citation in place)

| Language | n | MATCH | NEAR | UNATTRIBUTED | NO_APPROVED | UNRESOLVED |
|---|---:|---:|---:|---:|---:|---:|
| English | 130 | 13 | 19 | 38 | 0 | 60 |
| Urdu | 126 | 1 | 15 | 18 | 0 | 92 |
| Hindi | 94 | 3 | 3 | 19 | 0 | 69 |
| Tagalog | 85 | 0 | 1 | 15 | 0 | 69 |
| Bengali | 38 | 0 | 2 | 13 | 0 | 23 |
| **All** | **473** | **17** | **40** | **103** | **0** | **313** |

`NO_APPROVED_TRANSLATION` is zero throughout because every language collected
is one the index covers. The state is exercised by the existing suites, not
by this corpus.

For each of the 103 `UNATTRIBUTED` items, `tests/results_real.json` records
the closest approved translation and its score under `unattributed_review`,
so a human can see how near the miss was rather than taking the label on
trust. Most sit in the 0.55–0.75 band — close, but under the 0.75 `NEAR`
threshold.

### Latency

| | mean | p95 / max |
|---|---:|---:|
| Per quotation | 161 ms | 629 ms (p95) |
| Per document (~974 words) | 10.9 s | 29.3 s (max) |

Per-document latency is high enough to matter for a pre-publication gate and
is worth attention independently of accuracy.

### The headline finding

**Tier (a) located the publisher's cited verse in 262 of 262 cases — 100% —
and 194 of those correct answers were then discarded before the report.
Only 68 survived (26.0%).**

`find()` scores every span by text similarity, and `_resolve_overlaps` drops
anything below `SPAN_THRESHOLD` (0.55). A **partial** quotation — the normal
case in published da'wah writing, where an author quotes half a verse with an
ellipsis at each end — is by construction dissimilar to the whole verse. It
scores low. It gets dropped. A lexical match on a *different* verse can then
score higher and take the slot.

Worked example from the corpus, with the citation present and correct:

```
published:  "[He] who made for you the earth a bed [spread out]
             and the sky a ceiling…"  (Quran 2:22)

tier (a):   resolves 2:22 — correct — but scores 0.410
            0.410 < SPAN_THRESHOLD 0.55  ->  discarded
reported:   79:30, from the lexical tier, at 0.675
```

This failure mode is **invisible to a self-referential test**. Feeding whole
verses back from the index produces scores near 1.0, where the threshold never
binds. Partial quotation is near-universal in real writing and near-absent
from a test set built out of the index. That gap is the entire reason this
corpus exists, and finding it is the main thing the corpus bought us.

The diagnostic lives in `measure_reference_tier()` and is reported separately
from the aggregate rates, which hid it.

> We measured this; we did not fix it. `src/mizan/detect.py` is owned
> elsewhere, and a measurement harness that edits the thing it measures is
> worth nothing.

### The false-positive probe, and its severity split

This is the number that matters most. A gate that fires on ordinary prose is
worse than no gate: every spurious referral costs a reviewer's time and
teaches them to ignore the tool.

**120 paragraphs of no-quotation prose, across English, Hindi and Tagalog:**

| | count | rate |
|---|---:|---:|
| Paragraphs tested | 120 | |
| Paragraphs producing any finding | 46 | **38.3%** |
| Spurious findings total | 64 | |
| — of those, flagged for review (`UNATTRIBUTED`) | 62 | |
| — of those, **false attribution** (`MATCH` / `NEAR`) | **2** | **1.7%** |

Per language: English 32.5%, Hindi 45.0%, Tagalog 37.5%.

**38.3% is a bad number and should be reported as a bad number.** A gate that
fires on two-fifths of ordinary paragraphs would exhaust a reviewer.

But the severity split matters more than the rate, because these are not the
same error:

- A finding that lands in **UNATTRIBUTED** costs a reviewer one glance. The
  tool is saying "this matches nothing I have indexed — look at it." 62 of
  the 64.
- A finding that lands in **MATCH** or **NEAR** is a different error
  entirely. There the tool has **named an approved translation** and asserted
  that prose came from it. That is a false attribution, and it is the one
  error this system must never make. **2 of 64, on 120 paragraphs.**

So on this corpus MIZAN is noisy but it is not *lying*: it almost never puts
a publisher's name on text that publisher did not write. That is the right
way round for a referral gate, and it is a different claim from "the false
positive rate is low", which would not be true.

**Where the noise comes from, measured rather than guessed.** Every spurious
span is short, clustering hard against `MIN_SPAN_WORDS = 6`:

```
span width   min 6   median 7   max 17
47 of 64 findings are 8 words or fewer
```

Both false attributions were 6- and 8-word spans ("the Books of Abraham, the
Torah of Moses,"). A short window of ordinary religious prose shares enough
function words and enough theological vocabulary with *some* verse among
6,236 that the blended similarity clears threshold by coincidence. The floor
exists to prevent exactly this and is simply set too low for real prose; the
constant's own comment anticipates the failure, and this corpus shows it
happening at scale. `tests/results_real.json` records the full width
distribution under `spurious_span_widths` so the next person can see where to
move it.

## 4. What this does and does not show

### It does show

- MIZAN runs end to end on published prose from publishers who have never
  heard of it, in five languages, without crashing or hanging.
- The printed-reference tier is highly reliable at identifying which verse a
  publisher cited — and a specific, reproducible threshold interaction
  discards most of its answers before they reach the report. That is a
  concrete, actionable defect with a worked example and a named constant.
- Detection via the lexical tier alone is substantially harder on real text
  than on index text, and the per-language spread is wide.
- Whether the system falsely **attributes** non-scripture prose to a named
  approved translation, measured on prose from the same authors.
- Latency on realistic inputs, per quotation and per document.

### It does not show

- **How often publishers misquote.** We did not measure this, the corpus
  cannot support it, and the claim does not appear anywhere in this repository.
  These numbers describe MIZAN's behaviour. They say nothing whatsoever about
  publisher behaviour.
- **That any particular text is wrong.** `UNATTRIBUTED` means the rendering
  matches none of the approved translations **in this index**. The index holds
  22 translations across 5 languages. A narrow index produces more
  `UNATTRIBUTED` and that is a statement about our coverage, not about anyone's
  text. The prototype already proved this the hard way: passages we assumed
  were re-translated turned out to be Pickthall, which was simply missing from
  the index at the time.
- **A representative picture of da'wah publishing.** Two hosts. Not a random
  sample. Article selection came from category listings and sitemap strides,
  which is deterministic and reproducible but not statistically representative
  of anything.
- **Anything about a named publisher's quality.** Results are aggregated by
  host because the hosts have different document structures and that affects
  extraction. No host is characterised as good or bad, and no such conclusion
  is supported by this data.

### Known weaknesses of the corpus itself

- **Language balance is uneven**, and driven by what is ethically obtainable
  as HTML rather than by what we would have chosen. Bengali is the thinnest;
  `bn.wikipedia.org` via the Wikimedia dumps is the obvious next source.
- **Two hosts.** More would be better. Several candidates were rejected for
  good reasons (see §1) and we did not work around any of them.
- **Ground truth is the publisher's own citation**, not independent
  adjudication. Where a publisher's citation is itself imprecise, that
  imprecision passes straight through into the measurement.
- **Extraction is heuristic.** Spans are cut using CSS classes and quote
  glyphs. Some captured spans are hadith or scholarly quotations rather than
  Quranic ones, which depresses the apparent detection rate. Items whose
  paragraph carried no verse citation are excluded on the islamqa path for
  this reason, but the filter is not perfect.

## 5. Reproducing

**From the public repository.** The repository does not contain the
publishers' text (§6). It contains `data/real/corpus.manifest.json`: for every
record the source URL, the extractor's ordinal on that page, the printed
reference and a SHA-256 of the measured text — locators and checksums, no text.
Rebuild the corpus from the publishers' own pages with:

```bash
python3 scripts/rebuild_real_corpus.py              # fetch (cached, robots.txt honoured) + rebuild
python3 scripts/rebuild_real_corpus.py --offline    # from data/real/raw/ only
```

It runs the same extractor that built the original corpus, keeps only records
whose checksum matches, and reports every record dropped because its page was
edited since 2026-10-02. When anything was dropped, the eval's corpus
fingerprint differs from the reference and `results/SUMMARY.md` says so.

Note: `make real-corpus` prints that the extractor "has changed" since the
manifest was written. On 2026-10-04 the only change to
`scripts/collect_corpus.py` was the contact address in its User-Agent; the
extraction logic is the same, and an offline rebuild reproduces 473/473
quotations and 560/560 negatives.

**From scratch** (the original collection):

```bash
# collect (polite, cached, ~20 min — obeys robots.txt on every request)
python3 scripts/collect_corpus.py

# rebuild the corpus from cached HTML, no network at all
python3 scripts/collect_corpus.py --offline

# measure
python3 tests/real_corpus.py                  # full corpus, 120 negatives
python3 tests/real_corpus.py --limit 50       # quick pass
```

Outputs: `data/real/corpus.jsonl`, `data/real/negatives.jsonl`,
`data/real/manifest.json` (including the robots.txt audit trail), and
`tests/results_real.json`.

## 6. Licensing and the material itself

The text itself is not redistributed: `data/real/corpus.jsonl`,
`negatives.jsonl` and `raw/` are gitignored, and only the text-free
`corpus.manifest.json` is committed. Locally, each record stores only the
quoted span plus a short surrounding context, with the source URL retained for
attribution. This is quotation for non-commercial
research measurement, not redistribution as a reading edition. The raw HTML
cache under `data/real/raw/` exists so the measurement reproduces offline; it
is a crawl cache, not a publication.

If any rights holder objects to their material appearing in this measurement
set, the corpus can be rebuilt without that host by removing its entry from
`SOURCES` / `ISLAMQA_SITEMAPS` in `scripts/collect_corpus.py` and re-running.
