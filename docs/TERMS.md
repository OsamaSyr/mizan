# Panel 2 — Terminology lock

`src/mizan/terms.py` · collector `scripts/fetch_jamhara.py` · data `data/glossary/` ·
tests `tests/test_terms.py` · stdlib only · no model · no network at runtime

---

## 0. Why this panel exists

(MIZAN moved to Track 4 on 2026-10-04; this panel serves that track's
«الوصول إلى المعرفة الموثوقة» for shar'i terms. The original Track 2 framing
follows.)

Track 2's success criterion asks whether a solution preserved
«المعنى والدلالة الشرعية **ودقة المصطلحات**». Panel 1 answers that for scripture
(every quotation is attributed to a named approved translation). This panel
answers it for **terminology**.

The official scientific package names exactly one reference for it:

> الترجمة والمصطلحات — «موسوعة الجمهرة - مفردات المحتوى الإسلامي
> islamic-content.com/dictionary» — **«يقدم على الترجمة التلقائية في المصطلحات
> الشرعية الحساسة»**

It also gives a sample glossary in which every term carries a **ضابط الاستخدام**
(usage rule): الشريعة «لا يختزل في العقوبات أو القانون الجنائي», العبادة «لا تحصر
في الشعائر فقط», التوحيد «لا يختزل في ترجمة قد توحي بمجرد الوحدانية العددية».

So for every shar'i term in the Arabic source, Panel 2 asks one question:
**does the translation use the dictionary's approved equivalent, or an accepted
transliteration of it?**

It **flags and suggests**. It never rewrites the text and never authors a ruling,
and every suggestion names the dictionary page it comes from.

## 1. Using it

```python
import sys; sys.path.insert(0, "src")
from mizan.terms import check_terms

rep = check_terms(arabic, translation, "en")   # arabic may be None
rep.as_dict()
```

### Output contract (what `app.py` / `review.py` code against)

```jsonc
{
  "findings": [
    {
      "term_ar":     "الشريعة",                       // str | null
      "approved_en": ["The sharia", "Sharee‘ah", "Sharia", "Islamic law and guidance", "Shari'ah"],
                                                      // a LIST of str | null
      "status":      "VARIANT",                       // see §2
      "found":       "Islamic penal law",             // verbatim from the translation | null
      "suggestion":  "“Islamic penal law” reduces «الشريعة». Package rule (ضابط الاستخدام): «ولا يختزل في العقوبات أو القانون الجنائي». Approved: … Suggestion only — the wording is the editor's decision.",
      "source_url":  "https://islamic-content.com/dictionary/word/5979/en"
    }
  ],
  "counts": {"APPROVED": 0, "VARIANT": 1, "MISSING": 0, "NOT_IN_GLOSSARY": 0, "total": 1},
  // additive context, safe to ignore:
  "mode": "bilingual",            // or "translation_only"
  "lang": "en",
  "glossary": {"source": "jamhara+package", "terms": 271,
               "reference": "الجمهرة — islamic-content.com/dictionary"},
  "skipped_ambiguous": [],
  "notes": [],
  "unchecked_transliterations": 0 // consistency mode: words outside the glossary, COUNTED only
}
```

* **`approved_en` is a list.** It holds the dictionary's English title(s) first,
  then the package's English column, then up to two accepted
  transliterations. It is `null` when neither the dictionary nor the package
  gives an English equivalent for the term in this sense.
* **`suggestion` is a note for the editor, not a replacement string.** It is
  one English sentence generated by MIZAN's rules, with Arabic quoted in «»
  and the dictionary or package quoted where relevant. The terms to use are
  in `approved_en`. Nothing is ever substituted into the text.
* **`found`** is quoted verbatim from the translation, with case, apostrophes
  and diacritics preserved. It is never a normalised form, and it is only the
  words of the matched glossary form — never surrounding prose.
* **Every finding names a glossary term** (`term_ar` is never null). A
  transliterated word outside the glossary — usually a personal name — is
  never reported or quoted; consistency mode only counts them
  (`unchecked_transliterations`, and a sentence in `notes`), because app.py
  stores the report with the check.
* **`counts`** always has all four statuses (zeros included) plus `total`
  (= `len(findings)`).
* `check_terms(..., glossary=load_glossary(path))` is an optional keyword for
  tests and tools.

### Picking up the glossary automatically

`load_glossary()` keys its cache on the modification times of
`data/glossary/package_terms.json` and `jamhara.jsonl`. A server started before
the glossary existed switches from the package-ten fallback to the collected
glossary on its next request, with no restart
(`test_a_running_process_picks_up_the_glossary_when_it_appears`). When the files
are absent, `glossary.source` is `"fallback"` and `notes` says so.
`clarity.GLOSSARY` is built once at import, so a running server needs a
restart to pick up new *frozen* terms for Panel 3.

## 2. The four statuses

| Status | Meaning | Example |
|---|---|---|
| `APPROVED` | The translation uses an approved equivalent or an accepted transliteration | التوحيد → "Monotheism", "Tawhid", "Tawheed", "Oneness of God" |
| `VARIANT` | The translation uses a rendering we **recognise** but which is not the approved one. Three kinds: a reduction the package's ضابط الاستخدام rules out; a spelling neither الجمهرة nor the package attests; or (with no Arabic) one term spelled several ways in one text | الشريعة → "Islamic penal law"; العبادة → "rituals"; القرآن → "Koran"; "Tawhid … Tawheed" |
| `MISSING` | The term is in the Arabic, and no approved equivalent was found in the translation | الصلاة is present, but the translation never says Prayer, Salah or Salat |
| `NOT_IN_GLOSSARY` | MIZAN holds nothing it can check against | an Urdu translation; a term الجمهرة gives no English for in this sense |

Precedence in bilingual English mode:
1. A discouraged (reductive) rendering gives `VARIANT` — **checked first, and
   it wins over an approved rendering in the same text**. The usage rule is
   about how the term is explained: *"Tawhid here simply means numerical
   oneness"* uses the approved word and reduces it. When an approved rendering
   is also present the suggestion says so, and that a denial of the reduction
   (*"Sharia is not merely penal law"*, also `VARIANT` now) needs no change.
2. Otherwise an approved rendering gives `APPROVED`.
3. Otherwise an unattested spelling gives `VARIANT`.
4. Otherwise `MISSING`, unless the term is ambiguous (§4) or has no English equivalent (`NOT_IN_GLOSSARY`).

(Until 2026-10-04 rules 1 and 2 were the other way round — see §10.)

A discouraged phrase that is itself the approved rendering of **another** term
in the same Arabic is not blamed. «المناسك» → "Rites" is not a reduction of
«العبادة» (`test_discouraged_phrase_that_renders_another_term_is_not_blamed`).

### Where the "discouraged" lists come from

They come only from the package's ten usage rules, and they are kept
deliberately narrow. Each list is MIZAN's **reading** of one rule. It is
stored next to the rule it rests on (`basis` in `package_terms.json`), so a
reviewer can disagree with a single line rather than with the tool:

| Term | Rule it rests on (verbatim) | Discouraged renderings |
|---|---|---|
| الإسلام | ولا يختزل في معنى ثقافي عام | Islamic culture, Muslim culture, cultural identity, Muslim identity |
| التوحيد | ولا يختزل في ترجمة قد توحي بمجرد الوحدانية العددية | numerical oneness, numerical unity, unitarianism, monism |
| العبادة | ولا تحصر في الشعائر فقط | rituals, ritual, rites, rite, ritual practice, religious rituals |
| النبوة | مع التمييز بينها وبين القيادة الدينية البشرية | religious/spiritual leadership, religious/spiritual leader |
| الوحي | مع تجنب استعمالات فضفاضة قد توهم الإلهام الشخصي | inspiration, personal inspiration, intuition, spiritual insight |
| الشريعة | ولا يختزل في العقوبات أو القانون الجنائي | (Islamic) penal law, penal code, (Islamic) criminal law, punishment(s) |
| الفتوى | ولا يساوى بالمعلومة العامة | general information |

الحديث، السنة and الدعوة have no discouraged list. Their rules are about
context, not about a rendering that can be matched.

## 3. The glossary — how it was collected

### Ethics, enforced in code (`Fetcher`)

* robots.txt is re-read **live at the start of every run**, before any other
  request. If it is unreadable, the run aborts (fail closed). `--offline` uses
  the saved snapshot and opens no socket.
* The collector uses the **strictest applicable reading**:
  * the union of every `Disallow` in the `*` and `ClaudeBot` groups;
  * plus a hard deny on `/api/` and `/ayah/`, whatever robots.txt says;
  * and the largest `Crawl-delay`, which is 5 s, plus 0.5 s.

  The applied policy is `disallow /admin/ /api/ /attachment/ /ayah/ /config/
  /legacy-dictionary/`, with 5.5 s between requests.
* Requests are single-threaded, with User-Agent
  `Mizan-Research/0.1 (Islamic AI Challenge 2026; contact osamaabdullh2002@gmail.com)`.
* Every response is cached as gzipped raw HTML under `data/glossary/raw/`
  (625 files, 16 MB), indexed with its retrieval time in `raw/_index.json`.
  `--offline` rebuilds every output from cache, **byte-identically**
  (verified by `cmp`).

### Page structure (verified live 2026-10-03)

| URL | Content |
|---|---|
| `/dictionary` | landing page; links the 8 subject categories as `/dictionary/term/<cid>` |
| `/dictionary/term/<cid>` | the category's **full** word listing on one page: `<h2 class="post-title"><a href=".../dictionary/word/<id>">` followed by the vocalised title |
| `/dictionary/word/<id>` | the Arabic entry: a vocalised `<h1>`, breadcrumb categories, and definition blocks whose `<h5>` names the source work («من معجم المصطلحات الشرعية», «من موسوعة المصطلحات الإسلامية», «من الموسوعة الكويتية») with `<h2>` sections («المعنى الاصطلاحي», «التعريف», «الشرح المختصر», …). It ends with «ترجمة هذا المصطلح متوفرة باللغات التالية», linking `/dictionary/word/<id>/<lang>` |
| `/dictionary/word/<id>/en` | the English entry: `<h1>TITLE<br/>(عربي)</h1>`, where **TITLE is the approved English equivalent**, plus an English definition whose prose often names the dictionary's own transliteration (`"Tawheed" (monotheism)`, `"Salah" (prayer)`) |

So the English equivalent sits one link behind the Arabic page, exactly as the
page says. The collector follows that link only when the Arabic page lists
English. It never probes `/en` blindly.

### Choosing terms

The 8 category listings hold **12,689 unique entries**, most of them
specialist. A terminology lock is only useful on terms that occur in da'wah
material, and every page costs ≥ 5 s of the host's goodwill. So `SEEDS` in the
collector is a curated list of **304** introductory da'wah terms:
* the package's ten;
* the 31 core terms named in the brief;
* creed, worship, rulings, ethics, family law, da'wah, the Quran and hadith
  sciences, and sira.

Each seed is **resolved against the dictionary's own listing**. No URL is
guessed.

**Homographs.** Several seeds collide with other words once diacritics are
removed:
* unvocalised «الخطبة» is both the sermon and a marriage proposal;
* «القرآن» collides with «القِران»;
* «الإله» folds onto «الآلة» (a tool);
* «الإسناد» folds onto «الأَسناد».

Dictionary titles are vocalised, so seeds may carry vowels. `vowel_compatible`
rejects a title that disagrees with the seed on a short vowel, sukun or hamza
seat (`test_vowels_separate_homographs`).

**Sense review.** الجمهرة is the authority, but some of its pages contradict
themselves. Each `REVIEW` line in the collector was checked by reading the
entry's **own** Arabic and English definitions side by side. Nothing is
replaced or invented: the record keeps the dictionary's title verbatim and
carries the flag (`review` in `jamhara.jsonl`). The two flags mean:
* **`wrong_sense`**: the entry is a different word or sense, so `terms.py`
  does not load it.
* **`suspect_title`**: the definition matches, but the title does not. The
  dictionary's own transliteration is kept and the title is dropped.

## 4. Matching

### Arabic side

* `fold_ar` is MIZAN's frozen `engine.normalize` plus `arabic.fold_arabic`,
  with three exceptions, each one measured:
  1. Parentheses become spaces first. `normalize` deletes `(...)` (a
     translator's insertion in a verse), and prose often writes a term
     exactly that way: «(التوحيد)».
  2. **Ta marbuta is kept.** Folding ة→ه turns «عبادة» (worship) into
     «عباده» (*His servants*) and «القبلة» into «قبله» (*before him*). On the
     calibration below, that produced hundreds of false MISSINGs. The cost is
     that informal «الصلاه» is not matched, which is the safe direction for a
     flag.
  3. Alef maqsura is kept **during clitic analysis only**, so «وترى»
     (*and you see*) does not lose a "suffix" and become «وتر» (witr). For
     comparison, final ى and ي are the same letter, so «النبى» still matches
     «النبي».
* **Clitics:** و ف, then ب ك ل, then ال, including «لل» where the article's
  alef is elided.
* **Suffixes:** pronoun endings and sound plurals, restoring ta marbuta
  («صلاته» → «صلاة»).
* **Guards against inventing matches:** a proclitic is stripped only if 3+
  letters or an article remain («كبر» is not ك + «بر»). A suffix is stripped
  only if 3+ letters remain («حجة» is not «الحج»).
* **Longest match wins.** «المسجد الحرام» is one term and does not also report
  «الحرام». Ties are broken deterministically, preferring the least-stripped
  reading. An earlier version depended on Python's per-process hash order;
  `test_deterministic_across_processes` pins the fix.
* **Scripture is skipped.** Text inside ﴿ ﴾ is not checked. Scripture is
  Panel 1's job (attribution), not a terminology choice the publisher made,
  and §6 measures why.
* **Honorific formulas are skipped.** In «عليه الصلاة والسلام» and
  «والصلاة والسلام على رسول الله», the word «الصلاة» is a blessing that
  publishers render "peace be upon him". Read as the term, it flagged almost
  every Arabic text that names a prophet (`test_honorific_formulas_are_not_terminology`).
* **Ambiguity.** 73 terms are marked `ambiguous_ar`. Their unvocalised form is
  also an everyday word, a common verb, or a different word after folding:
  * «السنة» is also "the year";
  * «الكرسي» is also "the chair";
  * «الحدود» is also "the borders";
  * «البعث» is also the verb *He sent*;
  * «النذر» is also «النُّذُر» (*warnings*);
  * «الأذان» is also «آذان» (*ears*);
  * «الهدي» is also «الهدى» (*guidance*).

  An ambiguous term is confirmed when an approved or discouraged rendering is
  present, but it is **never reported MISSING**. Instead it is listed in
  `skipped_ambiguous`.

### English side

`latin_key` folds the ways transliterations of one word differ:
* diacritics, ʿayn/hamza marks and apostrophes;
* the article (as-Salah);
* doubled vowels (Tawheed, Salaah) and doubled consonants (Sunnah, Hajj);
* au/aw (Tauhid);
* the ta marbuta ending (Salah = Salat, Zakah = Zakat);
* plus a light plural/-ing/-ed strip.

English articles are skipped inside phrases, on both sides (the dictionary's
"People of scripture" matches "People of the Scripture"). The same folding is
applied to glossary and text.

Renderings of **different** terms may overlap. "Congregational prayer"
renders «صلاة الجماعة» and also contains "prayer", the rendering of «الصلاة».
When both terms are in the Arabic, both are found
(`test_a_rendering_inside_another_terms_phrase_still_counts`). Consistency
mode, which has no Arabic to say which term was meant, keeps only the
outermost hit, so "al-Masjid al-Haram" does not also report "Haram".

**Accepted transliterations** (`TRANSLITERATIONS` in `terms.py`, 232 rows,
247 spellings) are MIZAN-curated *spellings*, one or two per term. They are
accepted when used. They are never shown as the dictionary's equivalent, and
never shown as "Approved" for a term the dictionary gives no English for
(`test_a_curated_spelling_is_never_presented_as_an_approved_equivalent`).

A `!` in the table marks spellings that double as ordinary words or names
(Muslim, Hasan, Wali, Din). These are never scanned without the Arabic beside
them.

`SUBPHRASES` accepts a publisher's use of the head of a dictionary title.
For example, "Patience" counts for the title "Patience in adversity". Each
entry is verified at load time to be a literal sub-phrase of the dictionary's
own title, so the table cannot introduce a word the dictionary does not use
(`test_subphrases_must_come_from_the_dictionary_title`).

### Without Arabic (consistency mode)

Only what can honestly be checked:

| Situation | Status |
|---|---|
| A discouraged rendering in the **same sentence** as the term's own transliteration ("Tawhid here simply means numerical oneness") | `VARIANT` ("may reduce") — checked first |
| A transliterated term used consistently | `APPROVED` |
| One term spelled several ways in one text | `VARIANT` |
| An unattested spelling ("Koran") | `VARIANT` |
| A transliteration-shaped word outside the glossary | not reported; counted in `unchecked_transliterations` |

A word counts as transliteration-shaped if it has a macron or dot-below
letter, an ʿayn mark, or an apostrophe between letters that is not an English
contraction. Most of these are personal names, which is why they are counted
and never listed. A discouraged phrase elsewhere in the text is an ordinary
English word ("punishment") and is not judged without the Arabic.

Plain English words ("prayer", "mosque") produce nothing: without the source
there is no telling which Arabic term they render. Straight vs curly
apostrophe ("Qur'an" / "Qur’an") is typography, and "al-fitrah" vs "fitrah" is
the article; neither is counted as an inconsistency.

## 5. Languages — what can and cannot be checked

| Translation language | What Panel 2 does |
|---|---|
| English | the full check (§2) |
| Latin script (tl, id, ms, fr, …) | If the transliteration is kept → `APPROVED`. Otherwise `NOT_IN_GLOSSARY`. No guess is made about Tagalog or Indonesian words |
| Other scripts (ur, hi, bn, …) | `NOT_IN_GLOSSARY` for every term found, with the dictionary's own page in that language when it has one (e.g. `…/dictionary/word/3529/ur`) |

MIZAN collected English only. 137 of the 271 terms have الجمهرة pages in other
languages (recorded in `other_languages`). The pages cover id, ru, ur, fr, es
and bs; there are none for hi, tl or bn among them.

## 6. Measurement — the tool's behaviour, not a claim about publishers

> These numbers describe **what Panel 2 does** on real text. They are not, and
> must never be quoted as, a measure of how often any publisher misuses terms.
> No publisher or translation is named.

Reproduce: `cd src && python3 -m mizan.terms --measure`. This writes
`data/glossary/measurement.json`, with the full by-term breakdown, in about
10 s. The output is identical across `PYTHONHASHSEED` values.

### 6.1 English contexts in `data/real/corpus.jsonl` (the brief's measurement)

The corpus has **no Arabic side**, so this is consistency mode (§4) by
construction. `MISSING` cannot occur here.

What drives it:
* The material is written mostly in plain English (God, Paradise, Prophet,
  worship), which consistency mode deliberately does not judge.
* The findings are its transliterations: Quran (19 articles), Islam (13),
  Sahabah, mushaf, Kaaba, Zakat, Ramadan, Shirk, hadith, mutawatir,
  al-Masjid al-Haram, al-Masjid al-Aqsa and al-Lauh al-Mahfuz.
* The one `VARIANT` is a spelling the dictionary does not attest ("Koran").
* Two transliterated personal names are counted, not reported.

### 6.2 Calibration on approved prose — الجمهرة's own parallel definitions

These are 246 entries where the Arabic and English pages carry the same section
(e.g. «المعنى الاصطلاحي»), each run as a bilingual pair. The result is 236
findings: **APPROVED 179 (75.8%)**, MISSING 55 (23.3%), NOT_IN_GLOSSARY 1,
VARIANT 1. (Before 2026-10-04: APPROVED 180, VARIANT 0. The one change is a
definition of «العبادة» that uses both "worship" and "rituals"; with the
discouraged rendering checked first it is now a VARIANT whose suggestion says
the approved word is also present. One over-flag in 236, on the safe side.)

The dictionary's own English prose regularly renders a term with a word other
than that term's headword. For example, «القيامة» becomes "Day of Judgment"
rather than "Resurrection", and «الدعوة» becomes "advocacy" rather than
"Invitation". **MISSING is a prompt to look, not an error.**

### 6.3 Calibration on scripture — approved Quran translations

Every verse's Arabic was run against each of the 15 approved English
translations in MIZAN's index: 93,528 verse × translation pairs, with the ﴿ ﴾
skip not applicable. The result is 32,234 findings:

The MISSINGs are real rendering divergence between Quran translators and the

## 7. Feeding Panel 3 (clarity)

`clarity.py` freezes approved terms byte-exact before any adaptation. It now
loads them from `terms.clarity_entries()`:

* the package's ten hardcoded entries come **first and always win**;
* every accepted **transliteration** in the glossary is added, 343 frozen
  surfaces in total;
* a spelling of a package term (Tauhid, Shari'ah, Da'wah) is attached to the
  **package** entry, so it is glossed with the package's own rendering and
  constraint;
* plain-English equivalents are **not** frozen or glossed. الجمهرة renders
  النار as "Fire" and الإيمان as "Faith", and glossing *"the fire spread
  through the market"* as a shar'i term would be wrong
  (`test_plain_english_equivalents_are_not_frozen_or_glossed`);
* if `data/glossary/` is missing or unreadable, clarity degrades to the ten,
  never to an empty glossary
  (`test_glossary_degrades_to_the_package_ten_if_the_data_is_unreadable`).
  `clarity.GLOSSARY_SOURCE` says which.

Wiring this in exposed a clarity bug. Two apostrophe transliterations in one
sentence ("Da'wah … Shari'ah") read as an opening and a closing quote, so
ordinary prose was refused as SCRIPTURE. `_has_quote_marks` now ignores
apostrophes between two letters
(`test_apostrophes_inside_transliterations_are_not_quote_marks`).

## 8. Known limits

* **English only.** Other languages get the honest `NOT_IN_GLOSSARY`.
* **Some dictionary titles are not the usual English word.** Examples:
  "Heaven" for الجنة, "Unbeliever" for الكافر, "God-fearing" for التقوى,
  "Friday speech" for خطبة الجمعة. Panel 2 holds the dictionary to its own
  word, as the package instructs, and reports the divergence as a suggestion.
  It does not adopt translators' usage on its own authority.
* **Matching is lexical, not semantic.** A paraphrase that carries the
  meaning without the term ("calling people to God" for الدعوة) is MISSING. A
  title word used in an unrelated sense elsewhere in the translation can
  produce a false APPROVED.
* **Unvocalised Arabic stays ambiguous.** The ambiguity marks (73 loaded terms) trade recall
  for precision. They are a judgement, listed in `SEEDS`.
* **The review table reflects one reader's checking.** Every line cites the
  page's own definitions, and `--inspect` re-prints them.

## 10. What changed on 2026-10-04

Two defects predicted by an independent review, both reproduced first, both
with regression tests in `tests/test_terms.py`.

**Reductions next to the approved term were APPROVED.** `_bilingual_en`
returned `APPROVED` as soon as any approved form was present, before looking
at discouraged forms. Reproduced: *"Tawhid here simply means numerical
oneness"* (with «التوحيد») → `APPROVED`, found "Tawhid"; *"The Sharia is, in
this book, the penal code of punishments"* (with «الشريعة») → `APPROVED`;
the same in consistency mode. The package's usage rules forbid exactly these
reductions. Now discouraged renderings are checked first and win (§2); in
consistency mode, when one sits in the same sentence as the term's own
transliteration (§4). Both sentences are `VARIANT`, `found` = "numerical
oneness" / "penal code", with the rule quoted
(`test_reduction_next_to_the_approved_term_is_variant`,
`test_without_arabic_a_reduction_in_the_terms_own_sentence_is_flagged`). The
old test that pinned *"not merely penal law"* as `APPROVED` now pins it as
`VARIANT` with the "no change is needed" note
(`test_discouraged_rendering_wins_even_with_the_approved_term_present`).

**Personal names were stored.** With no Arabic, every transliteration-shaped
word outside the glossary became a `NOT_IN_GLOSSARY` finding with the word in
`found`. Reproduced: *"Ibn Mas’ud and Sa’id ibn Jubayr told Ḥamīda…"* →
findings `Mas’ud`, `Sa’id`, `Ḥamīda`, which app.py stores with the check. Now
a finding always names a glossary term and `found` is only the matched form;
words outside the glossary are counted (`unchecked_transliterations`, plus a
sentence in `notes`) and never listed
(`test_without_arabic_words_outside_the_glossary_are_counted_not_listed`,
`test_findings_only_carry_glossary_terms`).
